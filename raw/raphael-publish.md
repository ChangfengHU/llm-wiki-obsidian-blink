### 🎯 一句话定位
一个专为解决“微信公众号排版难”而生的现代 Markdown 引擎，通过强悍的剪贴板解析和微信 DOM 兼容处理，实现跨平台内容的无缝搬运与一键发布。

### ⚡ 核心功能
- **魔法粘贴（富文本转 MD）**：基于 `turndown` 深度定制，将飞书、Notion 或网页的富文本粘贴后瞬间净化为 Markdown，支持直接粘贴剪贴板图片。
- **微信兼容引擎 (`wechatCompat`)**：一键复制到公众号时，自动将外链图片转 Base64（绕过微信防盗链报错），并在底层重塑 DOM 解决微信列表、表格塌陷及多图并排断裂问题。
- **30套高定主题**：内置 Notion、飞书、少数派、GitHub 等 30 种高质量跨界主题，一键切换，告别公众号同质化排版。
- **多端预览与导出**：支持手机/平板/PC实时预览，并可导出为 PDF 或 HTML 文件用于存档分发。

### 🎭 适用场景
1. **自媒体与公众号运营者**：在 Notion、飞书等现代工具中完成写作，直接复制粘贴到该项目，一键排版并发布到微信公众号。
2. **技术博主/程序员**：习惯使用纯 Markdown 写作，需要解决微信公众号后台不支持 Markdown 且代码高亮极差的痛点。
3. **跨平台内容分发**：需要一份 Markdown 源文件，同时输出精美的微信图文和 PDF 格式报告。

### ✅ 是否值得深入研究
**值得（特别是对于前端和编辑器开发者）。**
它解决了一个极度垂直且痛点明确的场景。其源码结构清晰（React 18 + TS + Vite），没有臃肿的冗余代码。工程上的两大亮点：`wechatCompat.ts`（针对特定富文本编辑器的 DOM 降级与兼容处理）和 `htmlToMarkdown.ts`（剪贴板事件拦截与 AST 解析），是非常实用的前端工程参考案例。

### ⚠️ 主要缺点或风险
1. **Base64 图片的性能瓶颈**：为了绕过防盗链，将图片转为 Base64。如果文章极长且包含大量高清图，生成的剪贴板 Payload 会非常庞大，可能导致低配电脑卡顿或粘贴失败。
2. **重度依赖微信底层规则**：项目的核心价值（如 DOM 重塑）建立在微信现有的富文本编辑器缺陷之上。若微信官方大幅升级编辑器，部分兼容逻辑可能失效。
3. **纯工具属性**：仅提供排版与转换功能，不包含文档云端同步、图床管理等闭环功能，需配合其他写作软件使用。

### 🔗 与同类项目对比
相较于领域内老牌的 **Markdown Nice (mdnice)** 或开源的 **Doocs/md**：
- **优势**：UI 更加现代，主题设计审美极佳（引入了当前流行的效率工具风格）；“魔法粘贴”对飞书、Notion 的兼容解析体验更好；代码库较新，全量 TypeScript，无过度商业化痕迹。
- **劣势**：生态不如 mdnice，缺乏用户自定义 CSS 主题的社区集市，功能相对克制，不支持复杂的数学公式或自定义插件扩展。
