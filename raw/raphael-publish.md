### 🎯 一句话定位
一款专为微信公众号设计的纯前端 Markdown 排版引擎，通过“富文本自动转 MD”和“底层 DOM 重塑”，彻底解决公众号排版繁琐、图片防盗链及样式错乱的痛点。

### ⚡ 核心功能
1. **魔法粘贴（富文本逆向解析）**：拦截剪贴板，利用 `turndown` 将飞书、Notion 或网页的富文本瞬间转化为纯净 Markdown，免去手写烦恼。
2. **微信级 DOM 兼容与防盗链破解**：内置 `wechatCompat` 引擎重塑列表和表格 DOM 防止微信端塌陷；外链图片自动转 Base64，直接绕过微信“此图片来自第三方”的防盗链拦截。
3. **30套高质量预设主题**：独立设计各 Markdown 元素（代码块、引用等）的 CSS，一键切换 Notion、Claude、微信原生等高定排版风格。
4. **多图网格排版**：支持多图并排的响应式布局，且保证复制到微信编辑器后结构不折断。
5. **多端预览与多格式导出**：支持手机/平板/PC实时预览，并可直接导出为 PDF 或 HTML。

### 🎭 适用场景
- **微信公众号运营**：在 Notion/飞书写完草稿，直接粘贴进来，一键复制到微信后台，免去调格式和传图片的折磨。
- **技术博主**：需要发布包含大量代码块、表格的技术文章到微信公众号，且对代码高亮和排版审美有较高要求。
- **跨平台内容分发**：以 Markdown 为单点源，快速生成带样式的 HTML 或 PDF 用于存档、邮件发送或多平台发布。

### ✅ 是否值得深入研究
**结论：值得。**
- **业务侧**：精准切中了“公众号排版”这个长期痛点，功能克制但极其锋利（特别是图片转 Base64 和富文本粘贴）。
- **源码侧**：工程化标准高（React 18 + TS + Vite + Playwright E2E 测试）。其 `src/lib/wechatCompat.ts`（微信兼容处理）和 `htmlToMarkdown.ts`（剪贴板富文本解析）的源码，对于需要处理**富文本编辑器、剪贴板劫持、DOM 净化**的前端开发者来说，是极佳的参考范例。

### ⚠️ 主要缺点或风险
1. **纯前端架构的性能瓶颈**：由于没有后端图床，大量高分辨率图片被转为 Base64 后，可能会导致剪贴板体积过大，在低配机器或长图文场景下容易出现卡顿。
2. **强依赖微信 DOM 规则**：微信公众号编辑器的底层规则一旦发生大更新（例如严格限制 Base64 字符长度或更改过滤规则），核心的“一键复制”功能可能会瞬间失效，维护成本高。
3. **扩展性受限**：基于标准 Markdown 语法，不支持高度定制化的交互式公众号排版（如 SVG 动画、点击展开等高级运营特效）。

### 🔗 与同类项目对比
- **对比 Markdown Nice (mdnice) / Doocs**：
  - **优势**：技术栈更现代（Tailwind + Framer Motion UI 体验更好）；**魔法粘贴**功能极大降低了使用门槛（非程序员也能用）；自带图片 Base64 转换，免去了配置外部图床（如阿里云 OSS、GitHub 图床）的繁琐步骤。
  - **劣势**：生态较新，缺少 mdnice 庞大的社区自定义 CSS 主题库；不支持多平台（知乎、掘金等）的差异化一键分发，高度绑定微信。
