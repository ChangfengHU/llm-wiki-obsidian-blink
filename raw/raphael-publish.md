### 🎯 一句话定位
专为微信公众号打造的纯前端 Markdown 排版引擎，通过底层 DOM 重塑和自动化转换，彻底解决富文本粘贴、样式塌陷及图片防盗链三大痛点。

### ⚡ 核心功能
*   **富文本逆向解析（魔法粘贴）**：基于 `turndown`，将飞书、Notion、Word 复制的富文本直接反解析为纯净 Markdown，免去手动重写语法的繁琐。
*   **微信专属兼容引擎 (`wechatCompat`)**：一键复制时，自动进行底层 DOM 重塑，确保表格、列表等复杂排版在微信编辑器中不塌陷。
*   **图片自动 Base64 转换**：彻底解决微信公众号“此图片来自第三方”的防盗链报错，无需额外部署图床。
*   **开箱即用的高定主题**：内置 30 套精心设计的 CSS 主题，覆盖代码高亮、引用、表格等所有 Markdown 元素细节。

### 🎭 适用场景
*   **跨平台内容分发**：在 Notion / Obsidian / 飞书 中完成写作，直接复制粘贴到该工具，一键排版后同步至微信公众号。
*   **技术博主发文**：需要优雅展示代码块、复杂表格，且不想手动调整微信原生编辑器样式的开发者。
*   **轻量级文档导出**：利用其优秀的排版样式，将 Markdown 快速导出为美观的 PDF 或 HTML 文件存档。

### ✅ 是否值得深入研究
**结论：值得（特别是对前端工程师和内容创作者）**

**理由**：
1. **工程参考价值高**：源码是极佳的纯前端工具类 SPA 范例。深入处理了 `Clipboard API` 的拦截与解析、`markdown-it` 深度定制、以及针对特定宿主（微信编辑器）的 DOM 逆向兼容。
2. **切中刚需痛点**：没有做大而全的编辑器，而是极度聚焦“排版”与“微信兼容”，产品思路非常清晰。

### ⚠️ 主要缺点或风险
*   **Base64 转换的性能与体积瓶颈**：所有外链图片转 Base64 虽解决了防盗链，但若文章包含大量高清大图，可能导致剪贴板体积过大，在粘贴到微信时引发卡顿或超出微信字数/体积限制。
*   **极度依赖微信编辑器规则**：核心价值建立在微信公众号现有的富文本解析规则上。若微信官方大幅更新底层编辑器，该项目的 `wechatCompat` 逻辑可能瞬间失效，维护成本较高。
*   **纯前端无云端存储**：作为纯静态工具，若无完善的本地缓存机制（如 `localStorage` / `IndexedDB`），误关网页可能导致未导出的内容丢失。

### 🔗 与同类项目对比
*   **对比 mdnice (Markdown Nice) / Doocs (md)**：
    *   **优势**：技术栈更现代（React 18 + Vite + Tailwind），UI/UX 更贴合现代审美；**“魔法粘贴”（富文本转 MD）** 是巨大的差异化优势，而同类竞品通常要求用户必须手写或导入 MD 源码。
    *   **劣势**：生态积累不如 mdnice 深厚，mdnice 拥有庞大的用户自定义主题社区和更丰富的第三方插件支持。
