### 🎯 一句话定位
专为微信公众号打造的现代纯前端 Markdown 排版引擎，核心解决跨平台富文本粘贴、样式塌陷及微信图片防盗链的痛点。

### ⚡ 核心功能
*   **富文本“魔法粘贴”**：劫持剪贴板，将飞书、Notion 或任意网页的富文本一键净化并转换为纯净 Markdown（基于 `turndown`），支持直接粘贴图片。
*   **微信底层兼容引擎**：一键复制到公众号时，自动将外链图片转为 Base64（绕过微信“此图片来自第三方”防盗链机制），并重塑 DOM 结构防止列表/表格在微信中塌陷（核心逻辑在 `wechatCompat.ts`）。
*   **30+ 高定主题系统**：内置大量现代审美主题（如 Notion风、Claude风、飞书蓝），一键切换全局 CSS 内联样式。
*   **多端实时预览与导出**：支持手机/平板/PC三端实时预览，并提供基于 `html2pdf.js` 的 PDF 导出功能。

### 🎭 适用场景
1.  **公众号运营与技术博主**：习惯使用 Markdown 写作，但苦于微信原生编辑器极差的代码块和排版支持。
2.  **跨平台内容分发**：需要将 Notion、飞书、语雀中写好的图文，快速且无损地搬运到微信公众号。
3.  **前端开发者学习**：想学习如何处理复杂的富文本/Markdown 相互转换、剪贴板劫持，以及如何编写针对特定平台（微信）的内联 CSS 兼容黑魔法。

### ✅ 是否值得深入研究
**值得（特别是对于前端工程师和独立开发者）。**
*   **理由**：该项目的技术栈非常现代化（React 18 + Vite + Tailwind + TS），且工程化标准高（配备了 Vitest 单元测试和 Playwright E2E 测试）。它的价值不在于多高深复杂的底层算法，而在于**对特定业务场景痛点的精准打击**。其剪贴板处理逻辑（`htmlToMarkdown.ts`）和微信兼容层（`wechatCompat.ts`）是非常优秀的“小而美”工具开发范例。

### ⚠️ 主要缺点或风险
1.  **Base64 转换的性能隐患**：为了绕过微信图片防盗链，项目将图片转为 Base64。如果文章包含大量高清大图，生成的剪贴板数据会非常庞大，可能导致粘贴到微信后台时浏览器卡顿甚至崩溃。
2.  **平台规则依赖度高**：强依赖微信公众号当前的编辑器 DOM 解析规则。如果微信未来大幅修改其富文本编辑器的底层逻辑，该项目的兼容性引擎可能会瞬间失效。
3.  **缺乏后端与云同步**：作为纯前端静态项目，数据极大概率只保存在本地（LocalStorage）。不适合作为主力文档管理工具，仅适合作为“排版中转站”。

### 🔗 与同类项目对比
*   **对比对象**：Markdown Nice (mdnice)、Doocs/md。
*   **优势**：UI 交互更现代、审美更高级（使用了 Tailwind 和 Framer Motion，内置主题比传统的 mdnice 更符合当下流行的硅谷风/极简风）；“魔法粘贴”的跨平台富文本净化体验更平滑。
*   **劣势**：生态不如 mdnice 成熟。mdnice 拥有庞大的社区贡献主题库和插件系统，而本项目目前更像是一个高度定制化的个人/小团队利器，扩展性相对较弱。
