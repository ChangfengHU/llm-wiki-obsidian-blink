### 🎯 一句话定位
一个专为微信公众号打造的纯前端 Markdown 渲染引擎，通过“富文本自动转MD”和“底层 DOM 重塑”，彻底解决跨平台排版繁琐与微信图片防盗链痛点。

### ⚡ 核心功能
1. **魔法粘贴（剪贴板劫持与解析）**：基于 `turndown` 拦截从飞书、Notion 等平台的富文本复制，自动清洗并转换为纯净 Markdown，支持直接粘贴图片。
2. **微信兼容引擎 (`wechatCompat`)**：一键复制时，自动将外链图片转为 Base64（绕过微信防盗链限制），并重写 Table/List 的 DOM 结构，防止微信编辑器吞样式。
3. **开箱即用的高定主题系统**：内置 30 套精心设计的 CSS 主题（涵盖 Notion、GitHub、飞书等风格），一键切换，告别手写内联样式。
4. **所见即所得的多端预览与导出**：支持手机/平板/PC 实时预览，并基于 `html2pdf.js` 提供 PDF 和纯 HTML 导出能力。

### 🎭 适用场景
- **技术博主/自媒体**：习惯在 Notion、Obsidian 或本地写 Markdown，需要无损、免图床直接发布到微信公众号。
- **企业新媒体运营**：需要统一公众号文章的视觉规范，通过预设主题实现标准化排版，提高效率。
- **跨平台内容分发**：写一次内容，同时导出为公众号文章、PDF 报告或静态网页存档。

### ✅ 是否值得深入研究
**结论：值得。**
- **对于使用者**：它是一个极其高效的生产力工具，解决了“图床配置”和“样式错乱”两大核心痛点。
- **对于开发者**：代码库（React 18 + TS + Vite）结构清晰，包含完整的单元测试与 Playwright E2E 测试，工程化水平不错。其 `htmlToMarkdown.ts`（剪贴板解析）和 `wechatCompat.ts`（针对特定平台的 DOM 转换与 Base64 注入）源码，非常适合作为**富文本处理**和**剪贴板工程**的参考案例。

### ⚠️ 主要缺点或风险
1. **Base64 体积限制**：将外链图片全部转为 Base64 虽绕过了防盗链，但如果文章图片过多或过大，可能导致生成的 HTML 总体积超出微信公众号编辑器的字符/内存限制，导致保存失败。
2. **平台规则依赖**：高度依赖微信公众号当前富文本编辑器的底层逻辑（如对特定标签的过滤规则）。若微信未来大幅更新编辑器，项目需要及时跟进维护。
3. **纯前端无云端同步**：作为一个纯前端工具，目前看来缺乏账号系统和云端历史记录功能，更换设备或清理浏览器缓存可能导致未导出的草稿丢失。

### 🔗 与同类项目对比
相比于老牌的 **Markdown Nice (mdnice)** 或 **Doocs/md**：
- **优势**：现代化 UI 体验更好；**“魔法粘贴”**（直接解析飞书/Notion富文本）是杀手级功能；自动 Base64 处理极大降低了小白用户的图床配置门槛。
- **劣势**：生态沉淀尚浅，mdnice 拥有庞大的第三方主题市场和插件生态，而本项目目前主要依赖内置的 30 套主题，自定义扩展性相对有限。
