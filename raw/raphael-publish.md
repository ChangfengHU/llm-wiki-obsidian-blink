### 🎯 一句话定位
专为微信公众号打造的纯前端 Markdown 排版引擎，核心解决富文本粘贴净化与微信防盗链、样式兼容痛点。

### ⚡ 核心功能（3~5条）
1. **富文本“魔法粘贴”**：底层利用 `turndown` 拦截剪贴板，将飞书、Notion、Word 的富文本瞬间转化为纯净 Markdown，支持直接粘贴截图。
2. **微信生态特化适配**：一键复制到公众号时，利用 `wechatCompat` 引擎重塑 DOM 解决列表/表格塌陷，并将外链图片自动转 Base64 绕过微信防盗链。
3. **开箱即用的高定主题**：内置 30 套基于 CSS 变量设计的现代主题（如 Notion风、Medium风、暗黑模式等），告别传统公众号同质化排版。
4. **多端预览与导出**：支持手机/平板/PC实时预览，并集成 `html2pdf.js` 支持导出为 PDF。

### 🎭 适用场景
1. **技术博主/独立开发者**：习惯使用纯 Markdown 写作，需要快速发布到微信公众号且保持代码高亮和排版美观。
2. **内容运营人员**：需要将 Notion、飞书、语雀上沉淀的团队文档，无缝同步发布到微信公众号，免去二次排版折磨。
3. **轻量级文档生成**：需要快速将一段 Markdown 渲染为精美排版并导出 PDF 的临时办公场景。

### ✅ 是否值得深入研究
**值得（作为前端工具库和源码参考）**。
**理由**：虽然这是一个业务属性极强的工具，但其源码结构极其清晰（React 18 + TS + Vite）。特别是 `src/lib/wechatCompat.ts` (微信 DOM 兼容处理) 和 `src/lib/htmlToMarkdown.ts` (剪贴板富文本解析) 这两个文件，展示了如何优雅处理剪贴板劫持、DOM 净化、以及应对微信极其苛刻的富文本规则。非常适合想要学习**富文本处理**和**剪贴板操作**的前端工程师阅读。

### ⚠️ 主要缺点或风险
1. **Base64 图片体积隐患**：纯前端将图片转 Base64 注入微信后台，如果文章包含大量高清大图，极易导致复制失败、浏览器卡顿或触发微信编辑器字符上限。
2. **缺乏云端与图床能力**：纯前端 SPA 架构，无云端同步和自定义图床（如 OSS/腾讯云）直传功能，不适合作为主力的长期知识库。
3. **强依赖微信底层规则**：排版完美呈现高度依赖微信公众号当前的 DOM 解析逻辑，若微信后台编辑器发生重大更新，兼容引擎可能瞬间失效。

### 🔗 与同类项目对比
*   **对比 mdnice (Markdown Nice)**：mdnice 是老牌霸主，但目前已高度商业化、功能臃肿且需登录。本项目完全开源、纯前端、即开即用，体验更清爽现代。
*   **对比 doocs/md**：两者技术栈和定位相似。本项目的差异化优势在于**现代化的 UI/UX 设计**（Tailwind + 动画）以及对外部编辑器（Notion/飞书）的**剪贴板富文本解析（魔法粘贴）**支持得更深；劣势在于没有 doocs/md 丰富的第三方图床接入能力。
