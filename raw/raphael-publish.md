### 🎯 一句话定位
【FACT】专为微信公众号和内容创作者打造的现代 Markdown 纯前端排版引擎，主打“富文本逆向解析”与“一键无损粘贴至微信后台”。
*来源：GitHub README*

### ⚡ 核心功能
【FACT】
1. **魔法粘贴 (富文本转 MD)**：拦截剪贴板，利用 `turndown` 将从飞书、Notion、Word 或网页复制的富文本自动净化并转换为纯净 Markdown，支持直接粘贴截图。
2. **微信生态特化适配**：点击“复制到公众号”时，底层自动将外链图片转为 Base64（绕过微信防盗链报错），并通过 `wechatCompat` 重塑 DOM 结构防止列表/表格在微信中塌陷。
3. **30套高定样式**：内置数十套精心设计的 CSS 主题，独立控制背景、字体、代码块等元素的视觉呈现。
4. **多端实时预览**：提供手机 (480px)、平板 (768px)、PC 的所见即所得实时预览。
5. **本地导出**：支持通过 `html2pdf.js` 将渲染结果导出为 PDF 或 HTML 文件。
*来源：GitHub README / 代码结构*

### ✅ 是否值得深入研究
【INFERENCE】
**结论：值得（针对前端富文本处理与特定平台适配领域）**

**理由：**
- **信号1：解决了极度具体的业务痛点**。源码中的 `src/lib/wechatCompat.ts` 和图片 Base64 转换逻辑，是解决“微信防盗链”和“CSS 样式丢失”的优秀参考实现，对需要做微信生态集成的开发者极具价值。
- **信号2：优秀的剪贴板劫持与 AST/DOM 转换范例**。`src/lib/htmlToMarkdown.ts` 结合 `turndown` 实现了从复杂富文本（如飞书）到干净 Markdown 的降级转换，这是富文本编辑器开发中的常见难点。
- **信号3：工程化标准高**。作为一个纯前端工具，项目配置了 `vitest` 单元测试和 `playwright` E2E 测试，是学习 Vite + React 18 纯客户端工具开发的优秀开源模板。

### ⚠️ 主要缺点或风险
【INFERENCE】
- **缺点1：平台强依赖风险**。核心卖点高度依赖微信公众号后台当前的剪贴板解析逻辑。若微信未来升级编辑器（例如限制 Base64 图片大小或改变过滤规则），项目核心功能可能瞬间失效。
- **缺点2：纯前端处理多图长文的性能瓶颈**。图片转 Base64 虽然解决了防盗链，但在纯前端处理包含大量高清大图的长文时，会导致生成的剪贴板体积极其巨大，极易引起浏览器卡顿或微信后台粘贴失败（甚至崩溃）。
- **缺点3：缺乏云端存储体系**。纯静态架构意味着用户数据仅保留在本地浏览器缓存，清理缓存即丢失。

*对使用场景的影响：用户不能依赖该工具作为长期的文章管理中心，且在处理“多图+超长文”时可能会遇到粘贴失败的情况，需降级使用图床。*
